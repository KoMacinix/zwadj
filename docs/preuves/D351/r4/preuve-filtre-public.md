## 1. Le constat du BILAN : la liste et la carte appellent la MÊME fonction — LU DANS LE CODE FUSIONNÉ
`apps/api/src/venues/venues-public.service.ts` : `publicFilter(query, nowMs)` est une méthode privée, appelée par `list()` (`const { where, annotateOn } = this.publicFilter(query, Date.now())`) ET par `map()` (`const { where } = this.publicFilter(query, Date.now()); const located = { AND: [where, HAS_COORDINATES] }`). Le `where` de la carte est « le filtre de la liste ET avoir des coordonnées » ; le total de la carte (`count({ where })`) est celui de la liste. `PUBLIC_BASE_WHERE` (`publicationStatus = PUBLISHED`, `deletedAt = null`) et `status = ACTIVE` sont dans CE filtre : **une salle non publiée, supprimée ou masquée ne peut pas être dans la carte sans être dans la liste**. (Lecture adverse, contrôle R-4.a : `publicFilter` appelée 2 fois, `PUBLIC_BASE_WHERE` 3 occurrences.)

## 3. LES TROUS (R-4 : « un trou ⇒ entrée de backlog, pas de code ici ») — deux, et le second est MESURÉ
1. **« Sans créneau actif » (avec une date) n'est pas jouée SUR LA CARTE ; « compte du pro supprimé » ne l'est pas sous ce nom, mais c'est l'état « supprimée » (mesuré sur la carte).** Elles passent par `publicFilter` (le `slotTemplates: { some: ACTIVE_SLOT }` n'entre dans le filtre que quand une date est demandée ; l'approbation de la suppression d'un compte pro ARCHIVE ses salles vivantes : `deletedAt` posé, `account-deletion.service.ts`, D41 — donc le même cas que « supprimée », mesuré sur la carte), donc elles sont couvertes PAR CONSTRUCTION, et mesurées sur la liste (r50 M-2) ; aucune spec ne les ouvre sur la carte. Coût d'un test : une ligne de fixture dans `venue-map.int-spec.ts` (une salle sans créneau + une date) — un lot de test, à ordonner par Ko.
2. **Le `no-store` de la carte n'est affirmé par RIEN.** `getVenueMap` (`apps/client/src/lib/api.ts`) écrit `fetch(…/api/v1/venue-map…, { cache: "no-store", signal })` ; `api.test.ts` ne lit que le chemin et la requête (`new URL(appel).pathname`, `.search`, `endsWith("/api/v1/venue-map")`) ; aucune cible de `neutralize-ca1.py` à `ca6.py` ne mentionne `no-store`. **Mesure, par neutralisation de la mesure** : voir § 4.
   ⚠ **Nuance sur l'énoncé « la carte RESTE en no-store »** : la fonction est NEUVE (aucun « état d'avant »), et elle est appelée depuis le NAVIGATEUR (le commentaire de la branche le dit : « APPELÉE DEPUIS LE NAVIGATEUR, comme `countVenues` ») : le cache de DONNÉES de Next, objet de l'invariant de D348 (la fiche rendue par le serveur), ne la concerne pas ; `cache: "no-store"` écarte ici le cache HTTP du navigateur. L'invariant de D348 est tenu pour la fiche par `r50` M-3 et par la cible PUB1-20.
