## Un rejeu, dit — deux verts creux attrapés AVANT de figer les rouges

La première passe d'intégration (27 échecs sur 65, 38 verts) a été relue test par test avec `--reporter=verbose`. Elle montrait **un vert creux** : le test des énumérations du schéma (`rejects.toThrow()` sans message) passait **parce que la table n'existait pas** — n'importe quelle erreur le satisfaisait (D209 (1), « mesure confondue »). Il nomme désormais l'énumération dans le message de PostgreSQL (`invalid input value for enum "StaffRole"`…) et est rouge. La même relecture a montré que trois gardes de source (horloge, durées, journal) passaient sur **zéro fichier parcouru** (D290) : chacune exige maintenant ≥ 9 sources. Les pièces versées ici sont celles du **second jeu** (81 / 87 unitaires, 28 / 65 d'intégration) ; la première passe n'est pas versée (elle portait des fichiers qui ne sont plus ceux de l'arbre).

## Limites écrites

- Les tests ont été écrits contre une API que le code n'a pas encore : le spec de l'adaptateur (`staff-store.prisma.spec.ts`) est **volontairement couplé à l'ordre des instructions** (la séquence L1 → L4 du cadrage, § 3.1, est la preuve de l'absence d'interblocage). Un test peut donc se révéler faux au premier vert ; si l'un de ces fichiers doit être corrigé après le code, la correction est déclarée (sha256 avant / après) au rapport et dans la section D341.
- **Aucune mesure de concurrence n'a encore eu lieu** : les trois tests de concurrence (dix activations, vingt connexions, deux changements de mot de passe) sont de la classe `collecte` — ils ne s'exécutent pas avant le code.
