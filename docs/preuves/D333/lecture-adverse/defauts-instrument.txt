D333 — défauts de l'instrument de la lecture adverse (confronter-d332.py), trouvés à sa première passe et réparés ; la passe a été REJOUÉE EN ENTIER après chaque réparation (D298).
Première sortie : confronter-sortie-passe-1-AVANT-CORRECTIFS.txt (1a : abandon à la calibration ; 1b : passe complète avant les autres correctifs).
Aucun de ces défauts n'est un défaut de D332 : ce sont des erreurs de l'instrument, dont le mode d'échec est celui que le dépôt corrige (un extracteur qui répond sans avoir mesuré, D275).

1. `cibles_declarees` comptait deux fois chaque appel `cible(...)` écrit sur UNE ligne (deux expressions régulières qui se recouvrent). DÉTECTÉ par le bras de calibration « cibles déclarées, positif » (['A-1', 'B-2', 'A-1'] pour ['A-1', 'B-2']) : la passe s'est abandonnée avant tout contrôle (passe 1a). Réparé : une seule expression.
2. `campagne_cite` lisait le TEXTE de chaque campagne. Un COMMENTAIRE de `neutralize-solid-s7.py` (« Elle visait l'exemption de `src/dashboard/walkin-journey.test.tsx` ») fabriquait une huitième campagne retenue (N5, passe 1b) : l'union recalculée n'était pas celle de D332 à cause d'une définition plus large de « citer », pas d'un défaut de D332. Réparé : on lit les CHAÎNES du programme (ast), jamais ses commentaires ; un bras négatif a été ajouté (« le chemin n'est que dans un commentaire »). Ce que « citer » veut dire est désormais écrit dans la docstring.
3. T7 supposait que git STOCKE les trois fichiers d'autorité en CRLF. Faux : le blob est en LF pur (0 CRLF) ; c'est `core.autocrlf=true` qui les rend en CRLF dans l'arbre de travail. Réécrit en deux contrôles (T7 sur le blob, X7 sur l'arbre de travail) — et X7 est ce qui verra un `Edit` qui insérerait des LF nus dans un fichier d'autorité.
4. P6 et P7 supposaient que les pièces de portes de D331 ont le FORMAT de celles de D332 (« résumé 1 : fichiers passés … », « {'passed': …} »). Faux : D331 écrit « résumé : [((38, 0, 38), (468, 0, 468))] » et « résumé Playwright : 1 skipped · 53 passed ». Les deux contrôles rendaient None. Réparé en lisant le format réel de chaque pièce.
5. T6 cherchait l'entrée du backlog avec une expression en minuscules ; le titre est en MAJUSCULES (« LA CELLULE DE DÉTAIL D'UNE LIGNE « FIXE » EST VIDE »). Réparé en ancrant sur l'étiquette [PDF][À OBSERVER] et le titre exact.
6. N17 filtrait les commentaires sur la mauvaise sous-chaîne (le découpage d'une ligne `sha:chemin:n°:texte` sur le premier « : » laissait le motif ne jamais correspondre) : toutes les lignes de commentaire sortaient comme du code. Réparé : découpage en quatre champs, filtre sur le TEXTE ; et séparé en deux contrôles (production : aucune occurrence ; specs : leur garde de source, qui nomme ce qu'elle interdit).
7. N6 attendait (29, 27) sans lire que la sortie de l'union a été calculée sur l'ARBRE DE TRAVAIL de ce moment (la spec e2e réécrite n'était pas encore commitée). Le contrôle est devenu un ÉCART de D332 (imprécision de la pièce) ET un constat (N-C2), avec la preuve par git (la spec est absente du diff de 1f7b85f, présente à 970b7fa).
8. Un « constat » (S-C1) concluait « lu ainsi, il est exact » : ce n'est pas un constat, il est retiré. Et les identifiants des NON VÉRIFIABLES (N1, N3…) entraient en collision avec ceux de contrôles de la famille N : renommés NV-*.
9. Mécanique : deux tentatives de correctif par un heredoc Python dans la commande ont échoué sur l'enveloppe du shell (apostrophes), la règle de D289/D298 : le texte d'un correctif passe par un FICHIER, un script le lit.
